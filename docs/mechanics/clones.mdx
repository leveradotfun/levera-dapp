Every live coin is an **EIP-1167 minimal proxy** of `Launch`. Clones **cannot be upgraded**. A bug in `Launch` is permanent for every coin already created.

The factory stores `implementation` as `immutable`. A new factory is a new deployment. Old coins stay on the old impl until they die of their own accord.

## What that means

- Storage-layout changes to `Launch` are a **new implementation version**, not a patch.
- Check the new bytecode in the repo (`forge build` + `extract-abis.py`) and never point an old factory at a layout-incompatible implementation.
- Frontend/ui refuse to talk to a factory whose implementation they do not know. Record factory $\to$ implementation in `data/deployment.json` at deploy time.
- The implementation contract itself is constructed with `initialized = true`, so it can never be `initialize`d. Clones start uninitialized and are initialized in the same `createLaunch` transaction — no front-run window.
- Initialize revert string is `"init"` (shortened for the EIP-170 cap). Tests must use `vm.expectRevert(bytes("init"))` because `"init"` is ambiguous with `bytes4`.

## EIP-170

Robinhood is an Orbit chain with the 24,576-byte CREATE cap. `Launch` is compiled `via_ir = true`, `optimizer_runs = 1`. After `Launch.sol` edits:

```bash
forge build --sizes
forge test --match-contract 'LaunchTest|LaunchpadFactoryTest'
python3 extract-abis.py
```

Current margin is tight (on the order of tens of bytes). String shortening and early-return 1x fee path were required to fit.

## Migration path

1. Deploy new `Launch` implementation + new `LaunchpadFactory` + (if needed) new `LYC`.
2. Stop creating on the old factory (owner pause on LYC, or stop routing the UI at it).
3. Let old coins trade, graduate, and unwind. Do not try to `delegatecall`-upgrade clones.
4. LYC is **not** cloned. It can be replaced only by a new book: depositors redeem, then mint on the new LYC. There is no in-place migrate of liability.

Treat each `Launch` bytecode that changes storage slots as `Launch vN`.
