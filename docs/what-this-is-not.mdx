`HFYC.md` is the canonical mechanism spec. This site describes the same system from the implementation side.

| Rejected | Why |
|---|---|
| Morpho looping of raise ETH | Liquidation around a −17% ETH move, carry, mock ≠ Morpho, quoted depth that is not cash. |
| hyUSD **and** eHYUSD | One token. Price *is* the yield. |
| Naked-minting HFyc as “fees” | Dilutes depositors. Fee asset in, then mint at NAV. |
| Time-only funding as the yield engine | A 2-minute coin pays $\approx 0$ at any honest APR. |
| 3x target | Sell-into-dump has no time. Wipe at −33% ETH. |
| Instant $\$1$ redeem when $\mathrm{CR} \le 100\%$ | First-mover bank run. |
| Pairing as Uniswap LP | LPs take inventory risk; the meme would not get all the appreciation. |
| Reading Uniswap spot for NAV or a rebalance | Self-referential manipulation. Oracle values, DEX executes. |
| Fee lockups | Retired. Alignment is that HFyc is the senior of live 2x pools, not a time-lock. Knobs remain on the ABI and do nothing. |
| Hard 10% per-launch cap | Made the first coin on an empty book unpairable. Scarcity is **priced** via the occupancy curve instead. |
| ETH deposit queue that stays ETH | A dollar claim against unpaired ETH is already undercollateralized on the next tick down. ETH is sold to USDG on arrival; the protocol buys ETH back only at pair. |

<Note>
  `HFYC.md` is the mechanism spec and these pages describe the same system from the implementation
  side. Where either is more specific, it is because that is where the detail belongs — not because
  they disagree. If one ever does contradict the Solidity, the Solidity is right.
</Note>
